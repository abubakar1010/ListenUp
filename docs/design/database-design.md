# ListenUp Database Design

Oct 2, 2026 · @Md. Ebrahim Hossen

## 1. Summary and conventions

ListenUp uses **one PostgreSQL 16 database with six schemas and 32 tables**, designed so that the product's rules (one active attempt, two cards, three rounds, segment length, entry lock) are enforced by the database itself, not only by application code. It implements the data model of the [ListenUp Software Architecture](https://claude.ai/code/artifact/6a30920f-b6a0-4131-a486-f2044c71bb13) as refined by the [ListenUp System Design](https://claude.ai/code/artifact/98274889-96ba-4424-afad-c2cd056206e2).

### 1.1 Schemas

| Schema | Owner module | Holds |
| --- | --- | --- |
| `identity` | identity | Accounts, login sessions, one-time tokens, consents |
| `content` | content, transcript | Shared media objects, learners' content items, passage transcripts, reference profiles, per-learner transcript corrections |
| `practice` | practice, blind, dictation, review, cards, shadow | Sessions, steps, attempts, marks, cards, Shadow segments and rounds |
| `grading` | grading | Key points, gist and round grades, comparisons, trends, patterns |
| `ai` | ai | AI call log and quota usage |
| `ops` | platform, admin | Rate counters, idempotency keys, deletion audit, takedowns |
| `procrastinate` | platform | Job queue tables from the queue library's own SQL, vendored at the installed version and created by migration 0003; the database's search path includes procrastinate after public |

One schema per module makes ownership visible in every query (`practice.marks`) and lets each database role be granted exactly the schemas it needs.

### 1.2 Conventions

| Topic | Rule |
| --- | --- |
| Names | `snake_case`, plural table names, singular column names; foreign keys named `<table>_id` |
| Primary keys | `uuid`, version 7 (time-ordered), generated by the application; switch to `DEFAULT uuidv7()` on PostgreSQL 18 |
| Ownership | Every learner-owned table carries `user_id`, even when it can be reached through a parent, for row-level security and one-step deletion |
| Times | `timestamptz`, stored in UTC; every table has `created_at`; mutable tables have `updated_at`, maintained by one shared trigger |
| Audio positions | Integer milliseconds (`int4`); spans use `int4range` with half-open bounds `[start, end)` |
| Closed sets | `text` with a `CHECK (... IN (...))` constraint instead of PostgreSQL enum types, because adding a value is then a simple migration |
| Text limits | Every free-text column has a length `CHECK`, so a bad client cannot store megabytes |
| Flexible results | AI and speech outputs are `jsonb`; anything filtered or joined on is a real column |
| Deletes | Hard deletes with `ON DELETE CASCADE` from the owning parent; no soft-delete flags, which keeps deletion requests honest |
| Extensions | `citext` (case-insensitive email), `btree_gist` (exclusion constraints on spans) |

## 2. Entity relationships

All learner data hangs from two roots, `users` and `sessions`, while media, transcripts, reference profiles and key points are shared between learners and reached only through a learner's own `contents` row.

&#91;embedded content: entity relationships · 32 tables in 6 schemas\]

Read it from `sessions` outward: a session belongs to one content item, has 4 or 5 steps, attempts for its entry steps, marks, up to two cards, and one Shadow segment with three rounds. Grades sit beside the thing they grade.

## 3. identity schema

Accounts and login live here; secrets are never stored in readable form, only as hashes.

```sql
CREATE EXTENSION IF NOT EXISTS citext;
CREATE EXTENSION IF NOT EXISTS btree_gist;

-- Shared trigger: keep updated_at current on every mutable table.
CREATE FUNCTION public.touch_updated_at() RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
  NEW.updated_at := now();
  RETURN NEW;
END $$;

CREATE SCHEMA identity;

CREATE TABLE identity.users (
  id                uuid PRIMARY KEY,
  email             citext NOT NULL UNIQUE CHECK (char_length(email) <= 254),
  password_hash     text,                       -- Argon2id; NULL for Google-only accounts
  display_name      text CHECK (char_length(display_name) <= 80),
  email_verified_at timestamptz,
  status            text NOT NULL DEFAULT 'active'
                    CHECK (status IN ('active', 'pending_deletion', 'deleting')),
  deletion_scheduled_at timestamptz,          -- end of the 7-day grace period (DR-1)
  created_at        timestamptz NOT NULL DEFAULT now(),
  updated_at        timestamptz NOT NULL DEFAULT now(),
  CHECK ((status = 'pending_deletion') = (deletion_scheduled_at IS NOT NULL))
);
CREATE INDEX users_deletion_due_idx ON identity.users (deletion_scheduled_at)
  WHERE status = 'pending_deletion';
CREATE TRIGGER users_touch BEFORE UPDATE ON identity.users
  FOR EACH ROW EXECUTE FUNCTION public.touch_updated_at();

CREATE TABLE identity.auth_sessions (
  id           uuid PRIMARY KEY,
  user_id      uuid NOT NULL REFERENCES identity.users ON DELETE CASCADE,
  token_hash   bytea NOT NULL UNIQUE,           -- SHA-256 of the cookie value
  created_at   timestamptz NOT NULL DEFAULT now(),
  last_seen_at timestamptz NOT NULL DEFAULT now(),
  expires_at   timestamptz NOT NULL,
  user_agent   text CHECK (char_length(user_agent) <= 400),
  ip           inet
);
CREATE INDEX auth_sessions_user_idx    ON identity.auth_sessions (user_id);
CREATE INDEX auth_sessions_expires_idx ON identity.auth_sessions (expires_at);

CREATE TABLE identity.oauth_accounts (
  provider   text NOT NULL CHECK (provider IN ('google')),
  subject    text NOT NULL,                     -- the provider's stable user id
  user_id    uuid NOT NULL REFERENCES identity.users ON DELETE CASCADE,
  created_at timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (provider, subject)
);
CREATE INDEX oauth_accounts_user_idx ON identity.oauth_accounts (user_id);

CREATE TABLE identity.one_time_tokens (
  token_hash bytea PRIMARY KEY,
  user_id    uuid NOT NULL REFERENCES identity.users ON DELETE CASCADE,
  purpose    text NOT NULL CHECK (purpose IN ('verify_email', 'reset_password')),
  expires_at timestamptz NOT NULL,
  used_at    timestamptz,
  created_at timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX one_time_tokens_user_idx ON identity.one_time_tokens (user_id, purpose);
-- own_rows policy (section 9.2). Workers mint tokens, so the API may only SELECT and UPDATE.
GRANT SELECT, UPDATE ON identity.one_time_tokens TO listenup_api;
-- A reset link arrives before the learner is known: this marks a live token used and returns
-- its learner, or NULL when it is unknown, used or expired. The row lock makes it work once.
CREATE FUNCTION identity.consume_one_time_token(p_token_hash bytea, p_purpose text)
  RETURNS uuid
  LANGUAGE sql VOLATILE SECURITY DEFINER SET search_path = pg_catalog, pg_temp AS $$
  UPDATE identity.one_time_tokens SET used_at = now()
   WHERE token_hash = p_token_hash AND purpose = p_purpose
     AND used_at IS NULL AND expires_at > now()
  RETURNING user_id
$$;
REVOKE EXECUTE ON FUNCTION identity.consume_one_time_token(bytea, text) FROM PUBLIC;
GRANT EXECUTE ON FUNCTION identity.consume_one_time_token(bytea, text) TO listenup_api;

CREATE TABLE identity.consents (
  user_id      uuid NOT NULL REFERENCES identity.users ON DELETE CASCADE,
  kind         text NOT NULL CHECK (kind IN ('terms', 'privacy', 'voice_recording')),
  version      text NOT NULL CHECK (char_length(version) <= 20),
  granted_at   timestamptz NOT NULL DEFAULT now(),
  withdrawn_at timestamptz,
  PRIMARY KEY (user_id, kind, version)
);
```

- Login sessions are looked up by `token_hash`, so a leaked database copy cannot be used to log in. A request arrives with only its cookie, so the API first calls identity.resolve\_auth\_session(token\_hash), a SECURITY DEFINER function (section 9.2), and then sets the learner.
- A Shadow round can start only if a `voice_recording` consent row exists for the current version and `withdrawn_at` is NULL (checked by the shadow service, FR-SH-17).
- Password reset tokens are minted by the email job, never by the request, so a raw token is never stored in job arguments (ADR 0017). The job stores only the token's SHA-256 with a one-hour expiry and ends the learner's older unused reset links. A completed reset ends every login session of the learner and clears the sign-in lockout (section 7).

## 4. content schema

Media is stored once per source and shared; what a learner owns is a lightweight `contents` row pointing at it, and transcripts are cached per passage span rather than per clip.

```sql
CREATE SCHEMA content;

CREATE TABLE content.media_objects (
  id             uuid PRIMARY KEY,
  fingerprint    text NOT NULL UNIQUE,     -- 'youtube:<video id>' or 'upload:<user id>:<sha256>'
  source         text NOT NULL CHECK (source IN ('youtube', 'upload')),
  uploaded_by    uuid REFERENCES identity.users ON DELETE CASCADE,  -- NULL for YouTube
  source_ref     text CHECK (char_length(source_ref) <= 64),        -- YouTube video id
  title          text CHECK (char_length(title) <= 300),
  duration_ms    int4 CHECK (duration_ms > 0),
  has_video      boolean NOT NULL DEFAULT false,
  status         text NOT NULL DEFAULT 'pending'
                 CHECK (status IN ('pending', 'downloading', 'playable', 'failed', 'expired')),
  error_code     text,
  stage          text CHECK (stage IN ('checking', 'converting', 'saving')), -- ADR 0027
  playback_key   text,                     -- object storage keys
  video_key      text,
  peaks_key      text,
  playback_bytes int8,
  ref_count      int4 NOT NULL DEFAULT 0 CHECK (ref_count >= 0),
  last_used_at   timestamptz NOT NULL DEFAULT now(),
  created_at     timestamptz NOT NULL DEFAULT now(),
  updated_at     timestamptz NOT NULL DEFAULT now(),
  CHECK ((source = 'upload') = (uploaded_by IS NOT NULL))
);
CREATE INDEX media_objects_expiry_idx ON content.media_objects (last_used_at)
  WHERE status = 'playable' AND source = 'youtube';
CREATE INDEX media_objects_uploader_idx ON content.media_objects (uploaded_by)
  WHERE uploaded_by IS NOT NULL;
CREATE TRIGGER media_objects_touch BEFORE UPDATE ON content.media_objects
  FOR EACH ROW EXECUTE FUNCTION public.touch_updated_at();
CREATE INDEX media_objects_orphan_idx ON content.media_objects (updated_at)
  WHERE ref_count = 0;

CREATE TABLE content.contents (
  id              uuid PRIMARY KEY,
  user_id         uuid NOT NULL REFERENCES identity.users ON DELETE CASCADE,
  media_object_id uuid NOT NULL REFERENCES content.media_objects ON DELETE NO ACTION,
  title           text NOT NULL CHECK (char_length(title) BETWEEN 1 AND 300),
  keep_video      boolean NOT NULL DEFAULT false,
  created_at      timestamptz NOT NULL DEFAULT now(),
  updated_at      timestamptz NOT NULL DEFAULT now(),
  UNIQUE (user_id, media_object_id),       -- the same clip appears once per library
  UNIQUE (id, user_id)                    -- same-learner duplicate reference (ADR 0027)
);
CREATE INDEX contents_library_idx ON content.contents (user_id, created_at DESC, id);
CREATE INDEX contents_media_idx ON content.contents (media_object_id);

-- ADR 0020, migration 0006; queued_at and waiting index from ADR 0027, migration 0011.
CREATE TABLE content.uploads (
  id              uuid PRIMARY KEY,
  user_id         uuid NOT NULL REFERENCES identity.users ON DELETE CASCADE,
  storage_key     text NOT NULL UNIQUE,     -- users/<user id>/uploads/<upload id>.<ext>
  filename        text NOT NULL CHECK (char_length(filename) BETWEEN 1 AND 255),
  content_type    text NOT NULL CHECK (char_length(content_type) BETWEEN 1 AND 100),
  size_bytes      int8 NOT NULL CHECK (size_bytes > 0),
  content_id      uuid UNIQUE REFERENCES content.contents ON DELETE CASCADE,
  media_object_id uuid REFERENCES content.media_objects ON DELETE CASCADE,
  created_at      timestamptz NOT NULL DEFAULT now(),
  confirmed_at    timestamptz,
  queued_at       timestamptz,            -- NULL while waiting in the learner's queue (ADR 0027)
  CHECK ((confirmed_at IS NULL) = (content_id IS NULL)),
  CHECK ((content_id IS NULL) = (media_object_id IS NULL)),
  CHECK (queued_at IS NULL OR confirmed_at IS NOT NULL)
);
CREATE INDEX uploads_user_idx ON content.uploads (user_id, created_at);
CREATE INDEX uploads_unconfirmed_idx ON content.uploads (created_at)
  WHERE confirmed_at IS NULL;
CREATE INDEX uploads_waiting_idx ON content.uploads (user_id, confirmed_at, id)
  WHERE confirmed_at IS NOT NULL AND queued_at IS NULL;

-- ADR 0027, migration 0011: remember the removed duplicate and its retained item.
CREATE TABLE content.duplicate_uploads (
  content_id          uuid PRIMARY KEY,   -- the removed item; no row refers to it any more
  user_id             uuid NOT NULL REFERENCES identity.users ON DELETE CASCADE,
  existing_content_id uuid NOT NULL,
  created_at          timestamptz NOT NULL DEFAULT now(),
  FOREIGN KEY (existing_content_id, user_id)
    REFERENCES content.contents (id, user_id) ON DELETE CASCADE
);
CREATE INDEX duplicate_uploads_existing_idx
  ON content.duplicate_uploads (existing_content_id, user_id);
CREATE TRIGGER contents_touch BEFORE UPDATE ON content.contents
  FOR EACH ROW EXECUTE FUNCTION public.touch_updated_at();

CREATE TABLE content.passage_transcripts (
  id              uuid PRIMARY KEY,
  media_object_id uuid NOT NULL REFERENCES content.media_objects ON DELETE CASCADE,
  span            int4range NOT NULL CHECK (NOT isempty(span) AND lower(span) >= 0),
  origin          text NOT NULL CHECK (origin IN ('creator_captions', 'generated')),
  status          text NOT NULL DEFAULT 'pending' CHECK (status IN ('pending', 'ready', 'failed')),
  words           text[] NOT NULL DEFAULT '{}',
  start_ms        int4[] NOT NULL DEFAULT '{}',
  end_ms          int4[] NOT NULL DEFAULT '{}',
  confidence      int2[] NOT NULL DEFAULT '{}',   -- 0 to 1000
  sentence_starts int4[] NOT NULL DEFAULT '{}',   -- index of each sentence's first word
  provider_info   jsonb NOT NULL DEFAULT '{}',    -- provider, model, version
  created_at      timestamptz NOT NULL DEFAULT now(),
  updated_at      timestamptz NOT NULL DEFAULT now(),
  CHECK (cardinality(words) = cardinality(start_ms)
     AND cardinality(words) = cardinality(end_ms)
     AND cardinality(words) = cardinality(confidence)),
  -- Cached spans of one media object never overlap; a new passage stores only the missing part.
  EXCLUDE USING gist (media_object_id WITH =, span WITH &&) WHERE (status <> 'failed')
);

CREATE TABLE content.reference_profiles (
  passage_transcript_id uuid PRIMARY KEY
                        REFERENCES content.passage_transcripts ON DELETE CASCADE,
  model_version  text NOT NULL,
  phones         jsonb NOT NULL,   -- per word: [[phone, start_ms, end_ms], ...]
  pitch_cents    int2[] NOT NULL,  -- one value per 20 ms frame, 0 for unvoiced
  intensity_db   int2[] NOT NULL,  -- one value per 20 ms frame
  stats          jsonb NOT NULL,   -- speech rate, pause positions, stressed syllables
  created_at     timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE content.transcript_corrections (
  user_id               uuid NOT NULL REFERENCES identity.users ON DELETE CASCADE,
  passage_transcript_id uuid NOT NULL REFERENCES content.passage_transcripts ON DELETE CASCADE,
  word_index            int4 NOT NULL CHECK (word_index >= 0),
  corrected_text        text NOT NULL CHECK (char_length(corrected_text) BETWEEN 0 AND 60),
  created_at            timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (user_id, passage_transcript_id, word_index)
);
```

- **Why corrections are per learner.** Transcripts of a YouTube video are shared, so one learner's dispute (FR-TX-4) must not change what another learner is scored against. Corrections are an overlay applied when that learner's Dictation is scored. An admin can promote a correction to the shared transcript when several learners agree.
- **Reading a passage.** A session's passage may be covered by more than one cached span. The transcript service selects the rows whose `span && passage` (one GiST index lookup) and concatenates their words in time order.
- **Upload privacy.** An upload's fingerprint includes the uploader's id, so identical files from two learners never share a row. Confirmation stores a provisional `upload:<user id>:pending:<upload id>` fingerprint; conversion streams SHA-256 and removes a duplicate in favour of the older item. Conversion deletes the original after storing playback and peaks; both are under `users/<user id>/media/<media id>/` ([ADR 0020](../adr/0020-uploads-confirmed-against-a-pending-upload-table.md), [ADR 0022](../adr/0022-upload-conversion-dedup-and-media-delivery.md)).
- **Upload accounting and progress.** The cap counts playback bytes for playable clips, the original while preparing or while an upload can still be confirmed (24 h), and zero for failed clips. `queued_at` marks placement on the shared lane; `media_objects.stage` records checking/converting/saving, while the API derives queued/waiting and queue position. A removed duplicate resolves to 410 `duplicate_upload` with its retained item; another learner gets 404 ([ADR 0027](../adr/0027-intake-admission-progress-and-refusals.md)).
- **Why NO ACTION, not RESTRICT.** Both refuse to delete media that a content item still uses, but RESTRICT checks at once, so deleting an account failed when the cascade removed the learner's uploaded media before their content rows. NO ACTION checks at the end of the statement, after the cascade (migration 0005).

## 5. practice schema

The practice schema holds everything a learner does in a session, and most product rules are written here as constraints: an attempt can only exist for a step the session actually has, a session has at most one live attempt per mode, two card slots and three rounds.

```sql
CREATE SCHEMA practice;

CREATE TABLE practice.sessions (
  id              uuid PRIMARY KEY,
  user_id         uuid NOT NULL REFERENCES identity.users ON DELETE CASCADE,
  content_id      uuid NOT NULL REFERENCES content.contents ON DELETE CASCADE,
  passage         int4range NOT NULL
                  CHECK (upper(passage) - lower(passage) BETWEEN 30000 AND 900000),  -- 30 s to 15 min
  entry           text NOT NULL CHECK (entry IN ('blind', 'dictation', 'both')),
  current_step    text NOT NULL
                  CHECK (current_step IN ('blind', 'dictation', 'transcript', 'card', 'shadow', 'done')),
  entry_locked_at timestamptz,             -- set when Transcript opens (FR-PL-5)
  status          text NOT NULL DEFAULT 'active'
                  CHECK (status IN ('active', 'completed', 'abandoned')),
  version         int4 NOT NULL DEFAULT 0, -- optimistic concurrency
  created_at      timestamptz NOT NULL DEFAULT now(),
  updated_at      timestamptz NOT NULL DEFAULT now(),
  completed_at    timestamptz
);
CREATE INDEX sessions_user_idx    ON practice.sessions (user_id, updated_at DESC, id);
CREATE INDEX sessions_content_idx ON practice.sessions (content_id);

CREATE TABLE practice.session_steps (
  session_id   uuid NOT NULL REFERENCES practice.sessions ON DELETE CASCADE,
  user_id      uuid NOT NULL,
  step         text NOT NULL CHECK (step IN ('blind', 'dictation', 'transcript', 'card', 'shadow')),
  position     int2 NOT NULL CHECK (position BETWEEN 1 AND 5),
  status       text NOT NULL CHECK (status IN ('locked', 'open', 'done', 'skipped')),
  opened_at    timestamptz,
  completed_at timestamptz,
  PRIMARY KEY (session_id, step),
  UNIQUE (session_id, position),
  CHECK (status <> 'skipped' OR step IN ('card', 'shadow'))  -- only Card and Shadow can be skipped
);

CREATE TABLE practice.attempts (
  id          uuid PRIMARY KEY,
  session_id  uuid NOT NULL,
  user_id     uuid NOT NULL,
  mode        text NOT NULL CHECK (mode IN ('blind', 'dictation')),
  status      text NOT NULL DEFAULT 'active' CHECK (status IN ('active', 'submitted', 'voided')),
  started_at  timestamptz NOT NULL DEFAULT now(),
  finished_at timestamptz,
  -- An attempt can only exist for a step this session really has.
  FOREIGN KEY (session_id, mode) REFERENCES practice.session_steps (session_id, step) ON DELETE CASCADE
);
CREATE UNIQUE INDEX attempts_one_active ON practice.attempts (session_id, mode) WHERE status = 'active';
-- Same-learner foreign keys for Blind and Dictation (ADRs 0024, 0025).
ALTER TABLE practice.attempts ADD CONSTRAINT attempts_id_user_uq UNIQUE (id, user_id);

-- ADR 0024, migration 0009: anchor timing, attempt-bound media and the one resume.
CREATE TABLE practice.blind_attempts (
  attempt_id         uuid PRIMARY KEY,
  user_id            uuid NOT NULL,
  media_token_hash   bytea NOT NULL CHECK (octet_length(media_token_hash) = 32),
  media_expires_at   timestamptz NOT NULL,
  passage_start_ms   integer NOT NULL CHECK (passage_start_ms >= 0),
  passage_end_ms     integer NOT NULL,
  last_position_ms   integer NOT NULL,
  last_heartbeat_at  timestamptz NOT NULL,
  anchor_position_ms integer NOT NULL,
  anchor_at          timestamptz NOT NULL,
  buffering_ms       integer NOT NULL DEFAULT 0 CHECK (buffering_ms BETWEEN 0 AND 20000),
  resume_count       smallint NOT NULL DEFAULT 0 CHECK (resume_count BETWEEN 0 AND 1),
  resume_stop_ms     integer,
  void_reason        text CHECK (void_reason IN
                       ('left_page', 'reload', 'seek', 'missed_heartbeat', 'too_fast',
                        'interrupted')),
  gist_text          text CHECK (char_length(gist_text) <= 2000),
  CONSTRAINT blind_attempts_passage CHECK (passage_end_ms > passage_start_ms),
  CONSTRAINT blind_attempts_resume_stop CHECK ((resume_count = 1) = (resume_stop_ms IS NOT NULL)),
  -- The attempt's own learner, always (composite key, Database Design 5).
  CONSTRAINT blind_attempts_attempt_user_fk FOREIGN KEY (attempt_id, user_id)
    REFERENCES practice.attempts (id, user_id) ON DELETE CASCADE
) WITH (fillfactor = 70);

-- ADR 0025, migration 0010: versioned draft and same-learner attempt reference.
CREATE TABLE practice.dictation_attempts (
  attempt_id     uuid PRIMARY KEY,
  user_id        uuid NOT NULL,
  draft_text     text NOT NULL DEFAULT '' CHECK (char_length(draft_text) <= 20000),
  draft_version  int4 NOT NULL DEFAULT 0 CHECK (draft_version >= 0),
  submitted_text text CHECK (char_length(submitted_text) <= 20000),
  scoring_status text CHECK (scoring_status IN ('waiting_transcript', 'scored')),
  diff           jsonb,                  -- per reference word: status and what was typed
  accuracy       numeric(5,2) CHECK (accuracy BETWEEN 0 AND 100),
  scored_at      timestamptz,
  updated_at     timestamptz NOT NULL DEFAULT now(),
  -- The attempt and its learner together: never another learner's attempt.
  CONSTRAINT dictation_attempts_attempt_user_fk FOREIGN KEY (attempt_id, user_id)
    REFERENCES practice.attempts (id, user_id) ON DELETE CASCADE
);
CREATE TRIGGER dictation_attempts_touch BEFORE UPDATE ON practice.dictation_attempts
  FOR EACH ROW EXECUTE FUNCTION public.touch_updated_at();

CREATE TABLE practice.marks (
  id         uuid PRIMARY KEY,
  session_id uuid NOT NULL REFERENCES practice.sessions ON DELETE CASCADE,
  user_id    uuid NOT NULL,
  word_from  int4 NOT NULL CHECK (word_from >= 0),   -- positions in the passage word sequence
  word_to    int4 NOT NULL,
  at_ms      int4 NOT NULL CHECK (at_ms >= 0),
  tag        text CHECK (tag IN ('linking', 'reduction', 'weak_form', 'unknown_word')),
  note       text CHECK (char_length(note) <= 500),
  source     text NOT NULL CHECK (source IN ('dictation', 'manual')),
  status     text NOT NULL DEFAULT 'confirmed' CHECK (status IN ('suggested', 'confirmed')),
  created_at timestamptz NOT NULL DEFAULT now(),
  CHECK (word_to >= word_from),
  UNIQUE (session_id, word_from, word_to)
);
CREATE INDEX marks_session_idx ON practice.marks (session_id, at_ms);

CREATE TABLE practice.cards (
  id              uuid PRIMARY KEY,
  session_id      uuid NOT NULL REFERENCES practice.sessions ON DELETE CASCADE,
  user_id         uuid NOT NULL,
  slot            int2 NOT NULL CHECK (slot IN (1, 2)),   -- the two-card limit
  mark_id         uuid REFERENCES practice.marks ON DELETE SET NULL,
  media_object_id uuid REFERENCES content.media_objects ON DELETE SET NULL,
  written_form    text NOT NULL CHECK (char_length(written_form) BETWEEN 1 AND 100),
  heard_form      text NOT NULL CHECK (char_length(heard_form) BETWEEN 1 AND 100),
  snippet_key     text,                 -- 3 to 6 s clip; survives media expiry
  snippet_span    int4range,
  created_at      timestamptz NOT NULL DEFAULT now(),
  UNIQUE (session_id, slot)
);
CREATE INDEX cards_user_idx ON practice.cards (user_id, created_at DESC, id);

CREATE TABLE practice.card_reviews (
  id          uuid PRIMARY KEY,
  card_id     uuid NOT NULL REFERENCES practice.cards ON DELETE CASCADE,
  user_id     uuid NOT NULL,
  result      text NOT NULL CHECK (result IN ('heard', 'unsure', 'missed')),
  reviewed_at timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX card_reviews_card_idx ON practice.card_reviews (card_id, reviewed_at DESC);

CREATE TABLE practice.shadow_segments (
  session_id uuid PRIMARY KEY REFERENCES practice.sessions ON DELETE CASCADE,
  user_id    uuid NOT NULL,
  span       int4range NOT NULL CHECK (upper(span) - lower(span) BETWEEN 30000 AND 90000),
                                    -- 60 to 90 s, or the whole 30 to 60 s passage: trigger segments_span
  chosen_by  text NOT NULL CHECK (chosen_by IN ('system', 'learner')),
  mark_count int2 NOT NULL CHECK (mark_count >= 0),
  locked_at  timestamptz              -- set when round 1 starts; the segment can no longer change
);

CREATE TABLE practice.shadow_rounds (
  id               uuid PRIMARY KEY,
  session_id       uuid NOT NULL REFERENCES practice.shadow_segments ON DELETE CASCADE,
  user_id          uuid NOT NULL,
  round            int2 NOT NULL CHECK (round BETWEEN 1 AND 3),
  transcript_shown boolean GENERATED ALWAYS AS (round = 1) STORED,
  status           text NOT NULL DEFAULT 'recording'
                   CHECK (status IN ('recording', 'uploaded', 'analysing', 'scored', 'failed')),
  recording_key    text,
  recording_mime   text CHECK (recording_mime IN ('audio/webm', 'audio/mp4')),
  recording_bytes  int4 CHECK (recording_bytes BETWEEN 1 AND 5000000),
  duration_ms      int4,
  created_at       timestamptz NOT NULL DEFAULT now(),
  recorded_at      timestamptz,
  UNIQUE (session_id, round)
);
CREATE INDEX shadow_rounds_expiry_idx ON practice.shadow_rounds (recorded_at)
  WHERE recording_key IS NOT NULL;
```

- **Two cards without locks.** A card takes slot 1 or 2, and `UNIQUE (session_id, slot)` makes a third card impossible even when two requests race. Deleting a card frees its slot.
- **Round 1 shows the transcript, rounds 2 and 3 do not.** This is a generated column, so it can never disagree with the round number.
- **Shadow rounds hang off the segment,** so a round cannot exist before a valid segment does: 60 to 90 s, or the whole passage when the passage is 30 to 60 s.

Blind and Dictation attempt rows use `own_rows`; the API has `SELECT, INSERT, UPDATE`, with no independent draft deletion. `interrupted` records a second interruption, a device pause of 5 s or more, or an unreported pause beyond the anchor tolerance. The one resume (FR-BL-3) resets the 20 s buffering allowance and records `resume_stop_ms`; draft saves use `draft_version` to reject stale differing text with 409 `draft_conflict`, while an identical resend succeeds ([ADR 0024](../adr/0024-blind-heartbeats-resume-and-attempt-bound-media.md), [ADR 0025](../adr/0025-dictation-drafts-autosave-and-passage-player.md)).

## 6. grading schema

Every grade row has a `status` that moves from pending to a final state, so the interface always knows whether to wait, show a result or offer a retry, and every row records which provider, model and prompt version produced it.

## 8. Integrity rules

Every product rule that can be checked from the data alone is enforced by the database, so a bug in one service, a race between two requests or a manual fix in production cannot break it.

### 8.1 Where each rule lives

| Rule | Requirement | Enforced by |
| --- | --- | --- |
| One live attempt per session and mode | FR-PL-4 | Partial unique index `attempts_one_active` |
| An attempt only for a step the session has | FR-PL-2 | Composite foreign key to `session_steps` |
| A step opens only after the previous one is done or skipped | FR-PL-4 | Trigger `session_steps_order` |
| Only Card and Shadow can be skipped | FR-PL-7 | `CHECK` on `session_steps` |
| Entry choice cannot change once Transcript opened | FR-PL-5 | Trigger `sessions_entry_lock` |
| At most two cards per session | FR-CA-1 | `slot IN (1, 2)` plus `UNIQUE (session_id, slot)` |
| Shadow segment 60 to 90 s, or the whole passage when it is 30 to 60 s; fixed once round 1 starts | FR-SH-1 | `CHECK` on span plus triggers `segments_span` and `segments_lock` |
| Exactly rounds 1, 2, 3; transcript only in round 1 | FR-SH-2 | `CHECK`, `UNIQUE (session_id, round)`, generated column |
| Passage 30 s to 15 minutes | C2 | `CHECK` on `sessions.passage` |
| A child row belongs to the same learner as its session | NFR-SEC-2 | Composite foreign keys on `(session_id, user_id)` |
| Shared media is deleted only when unused | System design 6.2 | Trigger `contents_ref_count` plus `ON DELETE NO ACTION` |
| Cached transcript spans never overlap | System design 8.1 | Exclusion constraint |
| Transcript arrays stay aligned | System design 8.1 | `CHECK` on array lengths |
| A ready grade has its score and feedback | FR-BL-7, FR-SH-9 | `CHECK` on grade status |
| Blind timing, transcript visibility, consent before recording | FR-BL-1, FR-TX-5, FR-SH-17 | Services (they depend on time and requests, not only stored data) |

### 8.2 Triggers and added constraints

```sql
-- A step may open only when the step before it is done or skipped.
CREATE FUNCTION practice.check_step_order() RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
  IF NEW.status = 'open' AND NEW.position > 1 AND NOT EXISTS (
       SELECT 1 FROM practice.session_steps
       WHERE session_id = NEW.session_id AND position = NEW.position - 1
         AND status IN ('done', 'skipped')) THEN
    RAISE EXCEPTION 'step_locked: % cannot open before step %', NEW.step, NEW.position - 1
      USING ERRCODE = 'check_violation';
  END IF;
  RETURN NEW;
END $$;
CREATE TRIGGER session_steps_order BEFORE UPDATE OF status ON practice.session_steps
  FOR EACH ROW EXECUTE FUNCTION practice.check_step_order();

-- The entry choice is frozen once Transcript has opened.
CREATE FUNCTION practice.check_entry_lock() RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
  IF OLD.entry_locked_at IS NOT NULL AND NEW.entry IS DISTINCT FROM OLD.entry THEN
    RAISE EXCEPTION 'entry_locked' USING ERRCODE = 'check_violation';
  END IF;
  RETURN NEW;
END $$;
CREATE TRIGGER sessions_entry_lock BEFORE UPDATE OF entry ON practice.sessions
  FOR EACH ROW EXECUTE FUNCTION practice.check_entry_lock();

-- The Shadow segment is fixed once round 1 has started.
CREATE FUNCTION practice.check_segment_lock() RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
  IF OLD.locked_at IS NOT NULL AND NEW.span IS DISTINCT FROM OLD.span THEN
    RAISE EXCEPTION 'segment_locked' USING ERRCODE = 'check_violation';
  END IF;
  RETURN NEW;
END $$;
CREATE TRIGGER segments_lock BEFORE UPDATE OF span ON practice.shadow_segments
  FOR EACH ROW EXECUTE FUNCTION practice.check_segment_lock();

-- A Shadow segment is 60 to 90 s, or exactly the whole passage when the passage is 30 to 60 s.
CREATE FUNCTION practice.check_segment_span() RETURNS trigger LANGUAGE plpgsql AS $$
DECLARE
  p int4range;
BEGIN
  SELECT passage INTO p FROM practice.sessions WHERE id = NEW.session_id;
  IF NOT (upper(NEW.span) - lower(NEW.span) BETWEEN 60000 AND 90000
          OR (NEW.span = p AND upper(p) - lower(p) < 60000)) THEN
    RAISE EXCEPTION 'segment_span' USING ERRCODE = 'check_violation';
  END IF;
  RETURN NEW;
END $$;
CREATE TRIGGER segments_span BEFORE INSERT OR UPDATE OF span ON practice.shadow_segments
  FOR EACH ROW EXECUTE FUNCTION practice.check_segment_span();

-- Reference counting for shared media. SECURITY DEFINER: the API role may not update shared
-- media rows, yet adding a content item must count the reference.
CREATE FUNCTION content.count_media_refs() RETURNS trigger
  LANGUAGE plpgsql SECURITY DEFINER SET search_path = pg_catalog, pg_temp AS $$
BEGIN
  IF TG_OP = 'INSERT' THEN
    UPDATE content.media_objects SET ref_count = ref_count + 1, last_used_at = now()
     WHERE id = NEW.media_object_id;
  ELSE
    UPDATE content.media_objects SET ref_count = ref_count - 1
     WHERE id = OLD.media_object_id;
  END IF;
  RETURN NULL;
END $$;
CREATE TRIGGER contents_ref_count AFTER INSERT OR DELETE ON content.contents
  FOR EACH ROW EXECUTE FUNCTION content.count_media_refs();

-- Same-learner guarantee: children reference (session id, user id) together.
ALTER TABLE practice.sessions ADD CONSTRAINT sessions_id_user_uq UNIQUE (id, user_id);
ALTER TABLE practice.marks ADD CONSTRAINT marks_session_user_fk
  FOREIGN KEY (session_id, user_id) REFERENCES practice.sessions (id, user_id) ON DELETE CASCADE;
-- The same pattern applies to session_steps, cards and shadow_segments.
```

- Trigger errors use stable message prefixes (`step_locked`, `entry_locked`, `segment_locked`), which the API maps to the problem-details codes in the architecture's section 9.
- Row-level triggers also fire for rows removed by `ON DELETE CASCADE`, so deleting an account correctly decrements every shared media object's count.

## 9. Access control

Four database roles separate who can change the schema, who serves learners and who runs jobs, and row-level security makes the database itself refuse to return another learner's rows even if application code forgets a filter.

### 9.1 Roles

| Role | Used by | Rights |
| --- | --- | --- |
| `listenup_owner` | Migrations only | Owns all schemas and tables; never used by running services |
| `listenup_api` | API processes | Read and write learner tables, **subject to row-level security**; read-only on `ai.calls` |
| `listenup_worker` | Worker processes | Read and write all application tables with `BYPASSRLS` (jobs act for many learners); no DDL |
| `listenup_readonly` | Admin reports, debugging | `SELECT` only, with row-level security, on non-personal tables and on aggregates |

No role has superuser rights, and credentials for each come from the environment, not the repository. The baseline migration creates listenup\_api, listenup\_worker (BYPASSRLS) and listenup\_readonly as NOLOGIN roles when they are missing, with their timeouts (section 12.3), and never drops them; each environment enables login with a password from its secrets. The role that runs migrations takes listenup\_owner's place; on a managed database whose migration role is not a superuser, an administrator creates the roles once beforehand. Workers get rights on every application table through default privileges, while the API and read-only roles get explicit grants per table, so a new table stays closed to them until its migration opens it.

Explicit grants for the newly recorded tables: `content.uploads` permits `SELECT, INSERT, UPDATE, DELETE` ([ADR 0020](../adr/0020-uploads-confirmed-against-a-pending-upload-table.md)); `content.duplicate_uploads` permits only `SELECT` ([ADR 0027](../adr/0027-intake-admission-progress-and-refusals.md)); Blind and Dictation attempt rows permit `SELECT, INSERT, UPDATE` ([ADR 0024](../adr/0024-blind-heartbeats-resume-and-attempt-bound-media.md), [ADR 0025](../adr/0025-dictation-drafts-autosave-and-passage-player.md)); `ops.data_exports` permits `SELECT, INSERT`, while workers update status and archive metadata ([ADR 0030](../adr/0030-data-export-archive-built-in-the-background.md)). All use the `own_rows` policy below.

### 9.2 Row-level security

The API sets the current learner at the start of every transaction, and each learner table has one policy:

```sql
-- In the API, inside each request's transaction:
--   SELECT set_config('app.user_id', '<learner uuid>', true);   -- true = local to the transaction
-- After a transaction-local setting ends it reads back as '', not NULL, and ''::uuid would
-- raise an error instead of returning no rows, hence NULLIF. Migrations apply this policy
-- with enable_own_rows() from migrations/rls.py.

ALTER TABLE practice.sessions ENABLE ROW LEVEL SECURITY;
CREATE POLICY own_rows ON practice.sessions
  USING (user_id = NULLIF(current_setting('app.user_id', true), '')::uuid)
  WITH CHECK (user_id = NULLIF(current_setting('app.user_id', true), '')::uuid);
-- The same policy is applied to every table that has a user_id column:
-- identity.auth_sessions, identity.oauth_accounts, identity.one_time_tokens, identity.consents,
-- content.contents, content.transcript_corrections, all practice tables, grading.gist_grades,
-- grading.round_grades, grading.shadow_comparisons, grading.learner_trends,
-- grading.pattern_history, ops.idempotency_keys, content.uploads,
-- content.duplicate_uploads, ops.data_exports (ADRs 0020, 0027, 0030).

-- Before the learner is known, SECURITY DEFINER functions executable only by listenup_api
-- are the one way through: this one returns the learner of a live login session and nothing
-- else (identity.consume_one_time_token, section 3, does the same for an emailed token).
-- The API calls it first, then sets app.user_id.
CREATE FUNCTION identity.resolve_auth_session(p_token_hash bytea) RETURNS uuid
  LANGUAGE sql STABLE SECURITY DEFINER SET search_path = pg_catalog, pg_temp AS $$
  SELECT user_id FROM identity.auth_sessions
   WHERE token_hash = p_token_hash AND expires_at > now()
$$;
REVOKE EXECUTE ON FUNCTION identity.resolve_auth_session(bytea) FROM PUBLIC;
GRANT EXECUTE ON FUNCTION identity.resolve_auth_session(bytea) TO listenup_api;

-- Shared media: a learner sees a media object through their own content item or as its
-- uploader, and the API may insert only the learner's own uploads. Workers (BYPASSRLS) do
-- everything else: status, keys, YouTube media, expiry.
GRANT SELECT, INSERT ON content.media_objects TO listenup_api;
ALTER TABLE content.media_objects ENABLE ROW LEVEL SECURITY;
CREATE POLICY via_own_content ON content.media_objects FOR SELECT
  USING (uploaded_by = NULLIF(current_setting('app.user_id', true), '')::uuid
         OR EXISTS (SELECT 1 FROM content.contents c
                     WHERE c.media_object_id = media_objects.id
                       AND c.user_id = NULLIF(current_setting('app.user_id', true), '')::uuid));
CREATE POLICY own_uploads ON content.media_objects FOR INSERT
  WITH CHECK (source = 'upload'
              AND uploaded_by = NULLIF(current_setting('app.user_id', true), '')::uuid);
```

- If the setting is missing or empty, `NULLIF(current_setting(..., true), '')` returns NULL, the comparison is never true, and **no rows are returned**: a forgotten setting fails closed.
- Transcripts are not readable by the API role directly; the transcript service reads them with the worker role after checking that the session has reached the Transcript step (FR-TX-5). This keeps the hidden-transcript rule out of reach of an ordinary query.
- The integration suite runs every endpoint as a second learner and expects "not found" (architecture section 12).

## 10. Data lifecycle

Deletion removes storage objects first and database rows second, so a crash midway never leaves files that no row points to; retention runs as small scheduled sweeps on indexed columns.

### 10.1 Account deletion

1. The API sets `users.status = 'pending_deletion'` and `deletion_scheduled_at` to 7 days ahead, and ends all login sessions. The account is disabled at once; signing in before `deletion_scheduled_at` restores it (`status = 'active'`, `deletion_scheduled_at = NULL`).
2. When `deletion_scheduled_at` passes, a scheduled job (using `users_deletion_due_idx`) sets `users.status = 'deleting'` and writes an `ops.deletion_requests` row listing the storage prefix `users/<id>/` and the learner's upload media objects. The account can no longer sign in or be restored.
3. A background job deletes those storage prefixes and marks the request `storage_deleted`.
4. The job runs `DELETE FROM identity.users WHERE id = $1`. Cascades remove every learner row; the reference-count trigger decrements shared media.
5. The request is marked `completed` with a report of rows and objects removed.

Content, session and recording deletions follow the same order at a smaller scope.

### 10.2 Shared media

- A YouTube media object with `ref_count = 0` for more than 7 days is removed with its storage files; cascades remove its transcripts, profiles and key points.
- Upload media objects are removed together with their uploader's content row (an upload has exactly one reference).

### 10.3 Retention sweeps

| Data | Rule | Sweep (indexed) |
| --- | --- | --- |
| YouTube playback files | 30 days without use | `media_objects_expiry_idx`: delete the file, set `status = 'expired'`, keep transcripts |
| Shadow recordings | 90 days after recording | `shadow_rounds_expiry_idx`: delete the file, set `recording_key = NULL`, keep grades |
| Accounts pending deletion | 7-day grace period, then deleted (DR-1) | `users_deletion_due_idx`: start the deletion in 10.1 |
| Login sessions | Expired | `auth_sessions_expires_idx` |
| One-time tokens | Used or expired for 7 days | `one_time_tokens` |
| Idempotency keys | 24 hours | `idempotency_keys_age_idx` |
| Rate counters | Windows older than 1 day | primary key range |
| Export archives | Seven days after ready; delete object and mark request expired, retaining the row ([ADR 0030](../adr/0030-data-export-archive-built-in-the-background.md)) | `export.expire_archive`, queued transactionally when the archive becomes ready |
| AI call log | 90 days | Drop the monthly partition |

Sweeps delete in batches of 1,000 rows with `FOR UPDATE SKIP LOCKED`, so they never hold long locks:

```sql
WITH expired AS (
  SELECT id FROM content.media_objects
  WHERE status = 'playable' AND source = 'youtube'
    AND last_used_at < now() - interval '30 days'
  ORDER BY last_used_at
  LIMIT 1000
  FOR UPDATE SKIP LOCKED
)
UPDATE content.media_objects m
   SET status = 'expired', playback_key = NULL, video_key = NULL
  FROM expired e
 WHERE m.id = e.id
RETURNING m.id;   -- the job deletes the storage objects for these ids
```

When an expired YouTube media object is used again, intake downloads it afresh and sets it back to `playable`; its cached transcripts and profiles are reused.

## 11. Query patterns and indexes

Every frequent query is served by an index. The Blind heartbeat locks the attempt row, applies the pure judge and records its decision in one transaction ([ADR 0024](../adr/0024-blind-heartbeats-resume-and-attempt-bound-media.md)).

| Query | Frequency | Served by |
| --- | --- | --- |
| Blind heartbeat (check and update) | Every 5 s per learner in Blind | Primary key of `blind_attempts`, HOT update |
| Load a session with its steps | Every page load in practice | `sessions` primary key, `session_steps` primary key |
| Library list, newest first | Library page | `contents_library_idx` (keyset) |
| Sessions list | Home page | `sessions_user_idx` (keyset) |
| Passage words for a session | Dictation scoring, Transcript step | GiST exclusion index on `(media_object_id, span)` |

### 11.1 The heartbeat statement

The earlier single-UPDATE sketch is superseded by [ADR 0024](../adr/0024-blind-heartbeats-resume-and-attempt-bound-media.md): the service locks the active attempt row, calls the pure `judge(listen, beat, now)` and saves its continue, resume or stop decision in the same transaction. The transaction includes the row lock and save; the anchor clock prevents small per-beat advances from accumulating.

- Check the position against `anchor_position_ms` and `anchor_at`, within 1.5 s ahead and 6 s behind; buffering moves the anchor later, up to 20 s per listen.
- Hidden pages, backwards/out-of-passage seeks and more than 15 s without a heartbeat always void. A network stop is reported after 10 s without an answered beat; a device pause of 5 s or more or a second interruption records `interrupted`.
- The one eligible resume sets `resume_count = 1`, records `resume_stop_ms`, moves the anchor to `max(passage_start_ms, stop − 3000)` at the grant time, and resets buffering to zero. The rewind is an anchor change, not a forbidden backwards seek.
- Voiding updates the attempt status and reason together; a report after the passage is complete does not undo the completed listen.

### 11.2 Keyset pagination

```sql
-- Next page of the library after the last item shown (created_at, id).
SELECT id, title, created_at
  FROM content.contents
 WHERE user_id = $1
   AND (created_at, id) < ($2, $3)
 ORDER BY created_at DESC, id DESC
 LIMIT 20;
```

Indexes not listed in a DDL section are deliberately absent: each extra index slows writes and uses free-tier storage, so one is added only when a measured slow query needs it (`pg_stat_statements` is enabled to find them).

## 12. Size estimates, migrations and operations

A learner adds about **0.5 MB of database data per month**, so 150 learners fit a 0.5 GB free tier for roughly six months; migrations follow expand-and-contract rules so the app never stops for a schema change.

### 12.2 Migration rules (Alembic)

1. **Hand-written SQL.** Migrations are SQL run through `op.execute`, one Alembic revision per story (ADR 0013), because autogenerate cannot express most of the constraints, triggers and policies in sections 8 and 9. SQLAlchemy models mirror each table only so that `alembic check` reports drift. Every table with a `user_id` gets the `own_rows` policy from `migrations/rls.py`, and each new table needs explicit grants for `listenup_api`.
2. **Expand, then contract.** Add the new column or table, deploy code that writes both, backfill with a job, switch reads, and only then drop the old one in a later release.
3. **No long locks.** Every migration sets `lock_timeout = '5s'`; indexes are created with `CREATE INDEX CONCURRENTLY`; a new `NOT NULL` or foreign key is added `NOT VALID` and validated in a separate step.
4. **No big data changes inside migrations.** Backfills run as background jobs in batches.
5. **Reversible.** Each migration has a working downgrade, except drops, which come only after the contract step.
6. **Checked in CI.** Upgrade from an empty database, downgrade one step and upgrade again, `alembic check` for drift between models and schema, and a test suite that tries to break every constraint in section 8 and expects the database to refuse.
