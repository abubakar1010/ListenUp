# ADR 0028: AI ports, a minimal gateway and the self-hosted speech adapters

- Status: Accepted
- Date: 2026-10-04
- Implements: ADR 0009 (first part); issue #43; NFR-AI-1, NFR-AI-2, NFR-AI-3, NFR-AI-5, NFR-MNT-1
- Sources: [Software Architecture 7.1, 7.2, 7.5](https://claude.ai/code/artifact/6a30920f-b6a0-4131-a486-f2044c71bb13), [System Design 5.2](https://claude.ai/code/artifact/98274889-96ba-4424-afad-c2cd056206e2)

## Context

ADR 0009 puts all AI behind four provider-neutral ports and one configuration-driven gateway. Transcription is the first role the product uses, so the ports, the gateway entry point and the self-hosted transcription and alignment adapters must exist before the transcript story. The spikes that choose model sizes (#18, #19) have not run yet, and the speech libraries are large: they must not reach the API image, the default worker or CI.

## Decision

- **Ports** (`listenup/ai/ports.py`). `TranscriptionPort.transcribe(audio, language="en")`, `AlignmentPort.align(audio, text)`, `SpeechAssessmentPort.assess(recording, reference_text, reference_audio)` and `TextAIPort.generate(task, input, output_schema)` are async Protocols. Audio is a path to a local file the worker fetched; times are seconds. Results are frozen Pydantic models that reject unknown fields, negative times, an end before its start and scores outside 0 to 1, and each carries a required `provenance` of provider, model and version (NFR-AI-5). An alignment returns each word with its index in the reference text split on whitespace, so callers map it back; words a model cannot align (digits, symbols) are missing, never guessed. `unit_kind` says whether the units inside a word are phones or characters (the wav2vec2 aligner gives characters).
- **Configuration** (`listenup/ai/ai.yaml`, versioned in git). Each role has an ordered list of providers, each with `provider`, `model`, `timeout_seconds`, `retries`, `retry_backoff_seconds`, `preload` and adapter `options`. `LISTENUP_AI_CONFIG` points at another file; the packaged `ai.fake.yaml` selects the fakes. A provider name is resolved through `listenup/ai/registry.py`; a name with no adapter for its role, or a fake in production, stops the gateway from being built. Roles without an adapter yet (speech assessment, Text AI) have empty lists, and calling them raises `AIUnavailable`.
- **Gateway** (`listenup/ai/gateway.py`, `get_gateway()`). It builds each adapter once per process and calls the role's first provider under `asyncio.wait_for`. Timeouts, `ConnectionError` and `TransientProviderError` are retried with doubling backoff up to `retries`; any other error, or running out of attempts, raises `AIUnavailable`. The local speech providers have `retries: 0`, because a CPU timeout will not pass on a second try. Quotas, eligibility (`trains_on_inputs`), validation of value ranges beyond the schema, fallback to the next provider and the `ai.calls` log are left to #64.
- **Fakes** (`ai/providers/fake.py`), one per port, deterministic and model-free. Switching a role to `provider: fake` in `ai.yaml` changes the provider with no code change (AT-22 shape, tested through `LISTENUP_AI_CONFIG`).
- **Speech adapters.** `faster-whisper` (CPU, int8, model from `ai.yaml`, `base.en` until #18 decides) and `wav2vec2-ctc` (torchaudio's `MMS_FA` bundle, as in the spike harness, until #19 decides). Each is split at an engine: the engine is the only code that touches the library and returns plain data (`RawTranscription`, `RawAlignment`); a pure function maps that to the port's schema. The library is imported inside the engine, so it loads once per process, on first use or when the media worker preloads it (`preload: true`). `listenup.worker` preloads transcription and alignment in the media pool before writing its ready file; missing libraries stop the pool with a message. CPU threads are fixed per process (`OMP_NUM_THREADS=2` in the image, `cpu_threads` and `threads` options).
- **Dependencies.** `faster-whisper` is the optional `speech` extra in the lock; `uv sync` (CI, API image, default worker) leaves it out. The worker-media image adds it with `uv sync --extra speech`, then installs `torch` and `torchaudio` from the PyTorch CPU index, because the PyPI wheels bundle CUDA libraries the CPU server never uses. Models download on the first start into `/models` (a Compose volume locally).
- **Contract tests** (`tests/contract/`). Every file in `tests/contract/recordings/` is replayed through the whole adapter with an engine that returns the recorded raw output, and the result must be the port's schema and round-trip it. `scripts/record_ai_contract.py` records real engine output on a machine with the models.
- **Boundaries.** import-linter: only `grading` and `transcript` import `listenup.ai` (every module is a source, those two are carved out, so new modules are covered), and `faster_whisper`, `torch` and `torchaudio` are imported only from `listenup.ai.providers`. `tests/architecture/test_ai_boundaries.py` checks the same two rules by reading every file, including imports inside functions and through `importlib`, for a list of AI vendor libraries no file imports yet. The worker entry point may import `listenup.ai` to preload models; it is a composition root like its job registrations.

## Consequences

- Transcript and grading code depend on `ports` types and `get_gateway()` only; adding a provider is one adapter file plus one registry line.
- The recordings committed with this ADR are synthetic: hand-made in the engines' raw formats, because Hugging Face and the PyTorch download server were unreachable where the adapters were written. They prove the mapping and the schema, not the models. Replace them with real recordings (`scripts/record_ai_contract.py`) when #18 and #19 run on the stage 0 server.
- `torch` and `torchaudio` are not in the lock and not in the dependency audit; the worker-media image pins only a version range. Moving them into the lock with a `tool.uv` index for the CPU wheels is a follow-up once the lock can be resolved against that index.
- The first start of the media worker downloads the models (about 150 MB for `base.en` and 1.2 GB for `MMS_FA`), so its health check allows ten minutes. Running the media pool outside Docker needs `uv sync --extra speech` plus torch, or `LISTENUP_AI_CONFIG=src/listenup/ai/ai.fake.yaml`.
- A timed-out call to a local model keeps running in its thread until it finishes; with `retries: 0` it is not doubled.
