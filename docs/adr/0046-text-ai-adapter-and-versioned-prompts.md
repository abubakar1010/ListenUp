# ADR 0046: OpenAI-compatible Text AI adapter and versioned prompt files

- Status: Accepted; amends ADR 0041 on oversized input. Providers stay disabled until accepted (below)
- Date: 2026-10-19
- Implements: #66; NFR-AI-2, NFR-AI-3, NFR-AI-4, NFR-AI-5, FR-BL-12, FR-BL-13
- Related: ADR 0009, ADR 0028, ADR 0037, ADR 0041
- Sources: [Software Architecture 7.3, 7.5](https://claude.ai/code/artifact/6a30920f-b6a0-4131-a486-f2044c71bb13), [System Design 5.2, 7.3](https://claude.ai/code/artifact/98274889-96ba-4424-afad-c2cd056206e2)

## Context

ADR 0041 finished the gateway (eligibility, durable admission, validation, fallback) and left the Text AI adapters, prompts and their output formats to #66. ADR 0037 chose Groq `openai/gpt-oss-20b` as the hosted primary for key points and gist grading, and a local Ollama `qwen3:4b-instruct` as fallback and as primary for round feedback. Both speak the OpenAI-compatible chat API.

## Decision

**One adapter.** `ai/providers/openai_compatible.py` implements `TextAIPort` with `httpx` (already a dependency; no vendor SDK). The registry maps three provider ids to it: `groq`, `ollama` and `openai-compatible` (llama.cpp, vLLM). Separate ids matter because ADR 0041 keeps quota counters per provider id and rejects duplicate ids in a role. Everything that differs is an option: `base_url`, `api_key_env` (the *name* of an environment variable of the form `LISTENUP_AI_<NAME>_API_KEY`, so no other secret can be configured into a provider request; no key is ever in a file), `structured_output` (`json_schema`, `json_object` or `none`), `reasoning_effort`, `seed` and `deployment_version` (for example a model digest). A hosted entry must use `https`; plain `http` is accepted only for `local: true`. Because `local: true` also skips the consent, retention and region checks in `policy.eligible`, a local entry's `base_url` must name this host or the private network (a Compose service name, `localhost`, a `.internal` or `.localhost` name, or a private, loopback or link-local address); any other server must be configured as a hosted entry. The host is judged as the HTTP client reads it and must be plain ASCII, so `evil。com` (an ideographic full stop, `evil.com` to httpx) is refused; a single label the resolver reads as a number (`134744072`, `0x08080808`) and addresses that carry another address (IPv4-mapped public, 6to4, Teredo) are refused. A single label can be completed by a resolver search domain, so a local entry on a name is also checked where it resolves: before each request the adapter resolves the host and sends nothing unless every address is private, loopback or link-local (a name that resolves elsewhere is a permanent error; one that does not resolve is retryable). Address literals and hosted entries are not resolved. The check and the connection resolve separately, so it does not defend against DNS rebinding by a resolver the operator does not control. The logged version is `openai-chat-v1; structured=<mode>[; reasoning=<effort>][; seed=<n>][; deployment=<x>]`, naming every option that changes the output, resolved from configuration by `Registry.versions`, never from a reply.

**Request.** Temperature 0, `max_tokens` equal to the entry's `output_token_limit` (the effective, per-task cap from ADR 0041), no streaming. With `json_schema` the version's `<version>.schema.json` is sent as a strict `response_format`; with the other modes the schema is appended to the instructions. Every reply is validated against the task's Pydantic model (extra keys, out-of-range numbers and truncated replies are errors). The adapter does not retry: each retry needs fresh admission (ADR 0041), so an invalid reply is an error and the gateway moves to the next provider. HTTP 408, 429 and 5xx, timeouts and connection errors are retryable; other statuses and a missing key are `PermanentProviderError`. Errors never include reply text, which can echo the learner's words.

**Prompt files.** `ai/prompts/<task>/<version>.md` has YAML front matter (`task`, `version`, `status: active|retired`, `input_fields` with a `trim` flag) and the system prompt as its body; `ai/prompts/<task>/<version>.schema.json` is that version's output schema; the active version's must be the JSON Schema of the task's model in `ai/tasks.py` (a test fails if they differ). The schema is per version, not per task, so the stored `prompt_version` names the output format as well as the instructions: a new output format needs a new version, and a retired version keeps the schema it was used with. Exactly one version per task is active. `load_task(name)` returns `TextTask(name, version)` with the version read from the active file, so callers never hardcode one, the stored `prompt_version` and `ai.calls.prompt_version` change when the file does, and retired versions remain for comparing old results. `prompts/manifest.json` records every released file's SHA-256: editing a released prompt or schema needs a visible manifest change (`write_manifest()`), and a change in behaviour needs a new version. The manifest makes accidental edits visible; it cannot stop a reviewer-approved regeneration.

**Output formats.** `KeyPoints` (3 to 6, one `main` listed first), `GistGrade` (dimension scores `main_idea`, `key_details`, `accuracy` as integers 0 to 100, covered point ids, up to 5 wrong claims, feedback) and `ShadowFeedback` (feedback and 1 to 3 fixes). The overall gist score and level are computed by grading from the weights, never by the model.

**Input handling (amends ADR 0041).** ADR 0041 refuses oversized input rather than changing learner material. #66's acceptance criterion requires trimming. Both hold: `prompt_render.fit` shortens only *reference* text that the prompt file marks `trim` (the passage), at a word boundary, deterministically, with a `[truncated]` marker, before the gateway is called; it reports which fields it shortened. Learner text (the gist) is never trimmed and an over-long one is refused (`InputTooLarge`, or the gateway's refusal). `AIGateway.text_input_budget(task)` reads back the gateway's own admission rule (input limit less prompt overhead, per-task `task_budgets`, smallest across the task's providers), so `fit` and admission agree; admission and accounting are unchanged. Callers do not assemble these steps: `ai/text_tasks.run_task(gateway, name, input, Model)` reads the active version, fits the input to `text_input_budget` and then calls `AIGateway.generate`, returning the result and the names of the shortened fields. Trimming cannot be forgotten, and an over-long learner text is refused before admission, so it spends no quota. `generate` itself stays the unchanged #64 entry point and still refuses anything over budget. Budgets use the gateway's measure, UTF-8 bytes of the JSON input counted as tokens, which over-counts English by about four times: 7,000 stays under Groq's 8,000 tokens per minute with the output cap, and leaves about 6 KB for reference text.

**Injection defence (FR-BL-12).** Instructions are in the system message only. Every input field is one JSON object between `<<<DATA nonce>>>` markers with a per-call random nonce that the data is checked not to contain; the instructions state that the block is data and that the gist is untrusted. Only the fields a prompt file lists may be sent (FR-BL-13), and each task's input model in `ai/tasks.py` shapes them down to nested values (extra keys forbidden at every level, key point ids are the labels `kp1` to `kp6`, Shadow measures are the seven named in the Database Design, no type coercion), so an identifier cannot be added at any level. A refusal never quotes the input. Output validation rejects added keys, so an injected "overall: 100" cannot become a field.

**Providers and eligibility (NFR-AI-7, ADR 0037).** `policy.eligible` is unchanged. `ai.yaml` ships the Groq entry with `trains_on_inputs: false` from the services agreement, and `enabled: false`, `accepted: false`, `retention_verified: false`, empty `regions` and `populations`; the Ollama entry is `local: true`, `enabled: false`, `accepted: false`. Nothing is sent until an operator verifies limits, zero data retention and regions and the golden set passes (NFR-AI-6). Key points and gist grading are ordered hosted then local, round feedback local then hosted. "Enabled only when hosted quotas run out" is that order: the gateway reaches the local model only when it skips or fails the hosted one. The local model is the optional `llm` Compose service (profile `llm`, capped CPU and memory, `OLLAMA_CONTEXT_LENGTH=8192`), off by default so it takes no CPU from speech work.

**CI and keys.** No test opens a socket (an autouse guard fails one that does) and no key exists in CI or the repository (a test scans the config, prompts and recordings). Contract tests replay `tests/contract/recordings/text_ai/*.json` through `httpx.MockTransport`. `scripts/record_ai_contract.py text_ai` records a real reply from an environment key.

## Consequences and open items

- The first recordings are hand-written in each server's documented response shape, because no key or network was available. They prove request and response mapping, not model quality. Replace them with recordings made against the real services, and run the NFR-AI-6 golden set, before any entry is accepted.
- Groq's strict `json_schema` mode may not accept every schema keyword (`minItems`, `maxLength`); Pydantic revalidates, so a looser provider schema is safe, but this is unverified against the real service.
- The Ollama model digest is not pinned: the model registry was unreachable when this was written. The image is pinned by digest; pin the model with `deployment_version` once benchmarked (ADR 0037).
- The gateway logs an exception raised inside an adapter as `error`; `invalid_output` is reserved for its own validation step. Adapter-side validation failures therefore appear as `error` in `ai.calls`.
- A missing API key is detected after admission, so each attempt keeps its reservation charged (ADR 0041). Do not enable a hosted entry without its key.
- Trimming a passage for `extract_key_points` loses its tail; long passages need chunking, which is not built.
- The `suggestions` task (FR-SH-14) is outside this story. Grading logic that uses these tasks, including checking covered ids against the input, is not built here.
